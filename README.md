# FDS Evidence Studio · 인터랙티브 프로젝트 이해·분석 플랫폼

현재 제공 폴더에는 기존 웹 애플리케이션 소스가 없어 `dashboard/`에 독립 실행 모듈을 구현했습니다. 기존 서버에는 `Store`의 조회 메서드 또는 아래 API를 연결할 수 있습니다. 호스팅/외부 공개는 수행하지 않았습니다.

## Visual Storytelling: Explore / Workspace

Explore는 7개 장면의 스크롤 내러티브입니다. 지도와 시각 프레임은 고정되고, Intersection Observer가 읽고 있는 단계에 맞춰 연결 경로·입력/처리/출력·실제 차트 또는 연구 상태를 전환합니다. 노드와 수평 타임라인으로 원하는 장면에 바로 이동할 수 있습니다. 모바일의 전체 지도는 별도 모달로 엽니다.

Workspace에는 기존 기업·기간 선택, 8개 지표, 실제 종가, DuPont, 최초·정정 비교, 185개 검토행·9개 보완값, XML 검색과 개발 현황이 남아 있습니다. 모드 전환 시 기업·기간과 이야기 맥락을 유지합니다. 차트의 Hover/focus 기준 날짜는 다른 차트에도 비교 커서로 표시하며 재무값·가격을 보간하지 않습니다.

공시 근거는 우측 모달 패널로 열립니다. 수치 → 계산 → 계정 → 접수번호 → 원문 경로와 개별 공시 선택을 유지하고, 닫으면 원래 탐색 위치로 돌아갑니다. 용어는 Hover/focus에서 짧은 설명, Click/Tap에서 실제 관련 데이터·공식·변수·공시 및 기획 PT를 포함한 상세 패널을 엽니다.

기존 앱이 React 없이 동작하므로 데이터 조회 코드를 보존하면서 Motion의 공식 JavaScript 브라우저 엔진(14.5.0)을 사용했습니다. Motion은 텍스트·장면의 짧은 진입과 실제 차트 경로의 등장에만 사용합니다. 재무금액을 중간 가상값으로 카운트하지 않습니다. 라이브러리는 공식 npm 배포본을 로컬에서 제공하며 버전·출처·해시는 `motion-vendor.json`, MIT 라이선스는 `web/motion-LICENSE.md`에 보존합니다. 실행 때 CDN이나 npm 설치가 필요 없습니다.

OS의 `prefers-reduced-motion`을 따르고 Explore의 ‘동작 줄이기’로 직접 움직임을 줄일 수도 있습니다. 이 경우 Motion 실행과 부드러운 스크롤을 중단하고 정적 상태를 유지합니다. 전체 페이지 스크롤을 가로채는 스크롤 엔진은 사용하지 않습니다. 창 크기 변경 시 차트와 관찰 구간을 재설정합니다.

검증 기록: `visual-story-validation.json`. 1440×1000, 1024×900, 390×844에서 Explore와 Workspace 네 화면의 가로 넘침, 장면 이동, 우측 공시 패널과 실제 XML 조회, 모바일 분기/지도, 동일 날짜 커서, 동작 줄이기를 확인했습니다. ‘3분 내 이해’는 실제 사용자 평가가 남은 목표입니다. 최종 캡처는 `visual-story-explore.png`와 `visual-story-evidence.png`입니다.

참고한 원칙은 디자인을 복제하지 않고 연구 흐름에 재구성했습니다: [Vev scrollytelling](https://www.vev.design/guides/scrollytelling/), [Visme hotspots](https://support.visme.co/create-popup-effect/), [Motion animate](https://motion.dev/docs/animate).

## 시각화 중심 개편

첫 화면은 클릭 가능한 입력 데이터 → 임계 탐지 → 서서히/급락 → 통합 판단 → 사용자 의견 → 반박 → 결과 흐름도입니다. 기획 PT 2쪽을 확인하고 이번 요청의 단계 순서를 반영했습니다. 선택 노드·연결선·입력·알고리즘·출력을 함께 강조합니다.

- 화면은 프로젝트 지도, 실제 기업 분석, 모형 이해, 공시 탐색, 개발·검증 현황으로 나눕니다. 화이트/네이비/블루/틸/뮤트 바이올렛을 사용하고 주요 차트는 한 번에 크게 표시합니다.
- 공통 사전은 필수 용어를 포함한 17개 항목입니다. 작은 설명 버튼의 hover/focus/click/tap으로 한 문장 설명을 열고 별도 상세 패널에서 수식·변수·관련 실제 기업 관측·가정·한계·기획 PT 페이지를 확인합니다. 미구현 모형의 관련 입력과 실제 모형 출력을 구분합니다.
- L1 한눈에 / L2 실제 사례 / L3 기술·연구를 선택합니다. 실제 탐지가 없는 CUSUM의 L2는 가상 실험으로 별도 표시합니다. 사용한 가상 표준화 잔차 30개와 k/h 조절은 실제 기업의 금융 금액을 생성하지 않습니다.
- 실제 기업 분석은 8개 지표 선택, 시작일/분석일, 큰 시계열, 원천 근거, DuPont 입력 강조, 실제 KRX 종가, 최초·정정 관측 비교를 연결합니다. 종가는 수정주가 미검증 상태를 표시합니다.
- 근거는 수치 → 계산식 → 원천 계정 → 공시번호 → XML/DART 원문의 시각적 탐색 경로로 보여줍니다. 상세 입력과 표는 접어서 단계적으로 엽니다.
- 개발 현황은 산출물·검증 결과를 근거로 표시하며 임의 퍼센트를 쓰지 않습니다. 확인된 담당자 배정이 없으므로 미지정으로 표시합니다. 소스 수정 시각, 데이터 검증 시각, 다음 작업, 미확보·미검증 입력을 구분합니다.
- 사용자의 의견 입력은 현재 브라우저 메모리에만 유지하며 외부로 보내거나 자동 반박 결과를 생성하지 않습니다. 재로딩 시 사라집니다.

`ui-validation.json`에 1440×1000 및 390×844 브라우저 검증 범위와 한계를 기록했습니다. 17개 용어 상세, 5개 모바일 화면, 실제 그래프→XML, 정정공시, 가상 경보 변화, 키보드 포인트 선택을 확인했습니다. 실제 사용자 3분 이해도 평가는 별도 수행해야 합니다. 최종 화면은 `ui-overview.png`, `ui-glossary.png`, `ui-company.png`에 저장했습니다.

## 실행

PowerShell에서 프로젝트 루트의 `dashboard/start.ps1`을 실행하고 출력되는 로컬 주소를 엽니다. Python 3.10 이상이 필요합니다. 스크립트는 설치된 Python 또는 Codex 번들 Python을 찾습니다. 기본 포트는 8765이며 `-Port 8766` 등으로 변경할 수 있습니다. 종료는 서버 터미널에서 Ctrl+C입니다.

```powershell
& '.\dashboard\start.ps1' -Port 8765
```

직접 실행: `python dashboard/server.py --port 8765`. 기본 기능은 Python 표준 라이브러리로 실행됩니다. 일부 비정형 XML의 검색은 `lxml`이 필요하며 현재 Codex 번들 환경에는 설치되어 있습니다. 없는 환경에서는 명시적 안내와 공식 DART 링크를 제공합니다.

## 구현 범위

- 20개 기업 선택, 분석일 및 CFS/OFS 구분, 공시 이벤트 단위 8개 실제 지표 차트. 금액은 억 원, 비율은 %, 회전율은 배. 그래프는 지표 선택 방식으로 크게 표시합니다. CSV 원 단위 값은 상세에서 확인합니다.
- 기본 사례 켐트로닉스: 전체 범위에서 CFS 8개 지표 완비 17개 공시 시점. 메타바이오메드도 17개이며 XML 검토행 확보율까지 같은 경우 종목코드로 결정합니다. 기본 분석일 2019-12-31에는 21개 관측치가 있습니다. 전체 17개 완비 건수는 2020년 공개분도 포함하므로 분석일 내 건수와 다릅니다.
- 매출·영업이익 TTM의 지정 fact ID를 연결하고, 전년 연간 + 당해 누적 − 전년 동기 누적(4분기는 당해 연간)을 CSV 값과 대조합니다. 사용한 접수번호를 모두 제공합니다.
- NOA 입력은 기간·공시를 기준으로 원천 후보를 조회합니다. 확정 원천 행 ID가 없는 부분은 후보로 표시합니다. 지배기업 자본/순이익은 동일 접수번호·재무제표의 API 원천 계정 후보 및 검증·보완 표를 연결합니다. 지배기업 순이익 TTM의 분기별 원천 열 선택은 추가 검토 대상으로 남기며 검증 완료로 표시하지 않습니다.
- Evidence Explorer에서 185건 검증 및 신규 보완 9건을 기업·재무제표·분석일로 조회합니다. 원문 미표시, 해당 없음, 의미 검토 보류, 원문 미확보를 구분합니다. 검증 표의 상태는 검증 원본 CSV를 그대로 사용하며 전체 시계열을 검증 완료로 확대 해석하지 않습니다.
- 최종 패키지에 포함된 51개 공시 XML의 SHA-256을 근거 목록과 대조한 뒤 계정/금액 문자열을 검색·강조하고 표·행·인접 행을 표시합니다. 해시가 다르면 표시를 차단합니다. 검색은 회계 의미·금액·CFS/OFS의 자동 검증이 아닙니다. 원문 사본에 CFS와 OFS가 함께 있을 수 있으므로 문서 검색 결과의 재무제표 구분은 직접 확인해야 합니다.
- DART 특유의 표시 엔티티·비정형 마크업·인코딩을 원본 수정 없이 메모리에서 해석합니다. CP949 해석 또는 마크업 복구 시 화면에 알립니다. 표/행 번호는 검색용 0 기반 인덱스이며 원천 CSV와 파서 차이가 있을 수 있습니다.
- DuPont 설명은 금융 문제 → 실제 기업·시점 → 재무정보 → 계산 → 변화 그래프 → 해석·대안 설명 → 원문 근거의 순서입니다. 추가 금융모형·위험확률 등은 연구·개발 예정으로 표시합니다. 가상 재무금액을 사용하지 않습니다.

## 데이터와 보안

기본 데이터 디렉터리는 `OpenDART_보완통합본/OpenDART_TTM_팀원전달_최종본/`입니다. `DART_DATA_DIR` 환경변수로 변경할 수 있습니다. 지배기업 귀속 계정의 API 원천 후보는 이 폴더의 상위 `04_전체원본계정_통합.csv`에서 읽습니다. 이 파일이 없으면 후보 조회만 생략합니다. 최종본, 일별 CSV, 원문 및 API 키 파일을 수정하지 않습니다. API 키 파일을 읽거나 프론트엔드로 전달하지 않습니다.

서버는 127.0.0.1에만 바인딩하고 로컬 Host를 검사합니다. 허용 목록의 프론트엔드 파일와 지정된 기획 PT PDF와 선별된 JSON API만 제공합니다. 파일 경로·원본 CSV 전체·원본 XML 다운로드를 제공하지 않으며 로컬 절대경로도 API 응답에서 제외합니다. XML은 서버에서 텍스트로 추출하고 브라우저에서는 HTML로 실행하지 않습니다. 외부 스크립트/CDN을 사용하지 않습니다.

이 서버는 로컬 연구용이며 운영용 인증 서버가 아닙니다. 외부 공개가 필요하면 공시 사본의 이용 조건 검토, 인증·권한, 비공개 파일 저장소, API 제한을 갖춘 기존 백엔드에 이식해야 합니다. 현재 원문 사본 외부 재배포에 대한 법률·권리 검토는 완료되지 않았습니다.

## API

| GET | 역할 |
| --- | --- |
| `/api/catalog` | 20개 기업, 지표·단위, 기본 사례 선정 근거, 전체 검증 건수 |
| `/api/series?stock=089010&fs=CFS&asof=2019-12-31` | 분석일까지의 공시 시점 및 지표 값 |
| `/api/evidence?stock=089010&fs=CFS&asof=2019-12-31&receipt=20191113000024&metric=sales_ttm` | 계산 입력, 원천 계정, 모든 출처 공시, 합산 대조 |
| `/api/reviews?stock=052270&fs=CFS&asof=2020-12-31&kind=review` | 185건 중 해당 조건 검증 행 (`kind=addition`은 신규 보완값) |
| `/api/xml?stock=052270&asof=2019-12-31&receipt=20170331001179&q=지배` | 해시 대조 후 원문 텍스트 검색 (최대 40개 일치 행) |

모든 식별자는 문자열입니다. `asof`보다 나중에 공개되거나 이용 가능한 공시는 차단합니다. 각 과거 포인트에서도 그 포인트 이용 가능일을 넘는 출처를 차단합니다. 공시 메타데이터가 없는 수치는 NULL로 처리합니다. 정정본을 과거로 소급하지 않으며 OFS에서 지배기업 귀속 항목을 표시하지 않습니다. 전체 패키지 검증 요약은 수치가 아닌 재료 현황으로 별도 표시합니다.

## 검증

```powershell
python -m unittest discover -s dashboard -v
python dashboard/verify.py
```

검증은 전체 그래프 값과 최종 CSV 일치, NOA/DuPont 산식, TTM 원천 금액 합산, KRX 실제 종가 일치 및 기간 제한, fact ID의 기업·CFS/OFS·시점 연결, 미래/미등록 공시 차단, 185/9건 집계, 51개 원문 해시와 검색, HTTP 응답 및 원본/비밀 파일 경로 차단을 다룹니다. `verify.py`는 별도 `dashboard/validation.json`에 결과를 생성합니다. 원본을 덮어쓰지 않습니다. 이는 연결·계산 검증이며 모든 계정의 회계적 의미를 새로 수동 검증했다는 뜻이 아닙니다.


## 수식·데이터 계보와 문구 개편 (2026-10-21)

메인 제목과 7단계 설명을 제공된 문구 지시서에 맞게 수정했습니다. 기존 스크롤 연동·공시·차트·용어 사전은 유지합니다.

모형 화면의 ‘금융모형 수식·데이터 계보’에서 실제 기업·공시 시점을 선택합니다. 매출/영업이익 TTM, NOA, 평균 NOA, ATO, PM, OpROA를 역할 → 선택 가능한 공식 → 실제 값 대입 → CSV·공시 계보 순서로 탐색합니다. 그래프 포인트의 근거 패널과 주요 용어 상세에서도 같은 계보를 엽니다. F-Score 9조건, Ohlson 잔여이익, CUSUM은 실제 계산과 미확보 입력을 구분하며 임의 점수·가치·경보를 생성하지 않습니다.

- `/api/lineage?stock=089010&fs=CFS&asof=2019-12-31&receipt=20191113000024&metric=ATO`: 선택한 이벤트의 변수·원천 행·방향 그래프·금액 대조·공시 메타데이터.
- `/api/schema`: 01·02·03·08·25·26·매핑표의 실제 헤더와 명시적 변수 매핑. 데이터 전체를 반환하지 않습니다.
- NOA 계보는 기존 12번 생성 코드 `point_fact`의 최신 이용 가능일·당기 기준 공시 우선·최신 접수번호·단일 금액 규칙을 재현한 뒤 최종 CSV와 대조합니다. 이는 저장된 확정 fact_id와 구분됩니다. 후보만 제공하던 기존 근거 패널에 더해 새 계보 패널에서 선택 규칙·금액 일치를 확인합니다.
- TTM은 25번의 명시적 fact_id 합산을 확정 계산 경로로 사용합니다. 03번 최근 4분기도 표시하되 분기 합계와 최종 TTM의 버전이 다르면 동일 구성항으로 확정하지 않습니다. 동일 키의 분기 금액이 충돌하면 값을 표시하지 않습니다.
- 계정 ID·BS/IS/CIS/CF가 02번 원천에 없으면 추정하지 않습니다. 귀속 자본·순이익의 원본 API 후보에는 실제 ID·열을 표시하되 TTM 열 선택을 검증 완료로 확대하지 않습니다. 선택한 공시의 실제 검토·보완 결과도 함께 제공합니다.
- 원천 XML의 지정 표 안에서 계정명과 원문 금액을 강조합니다. 표/행 번호는 0 기반 검색 위치이며 회계 의미 검증과 다릅니다. 사본이 없으면 공식 DART 링크를 제공합니다.
- OpROA 전기 변화는 `ΔPM × 평균 ATO + ΔATO × 평균 PM`의 대칭 분해를 화면에서 계산합니다. 각 기여도의 단위는 %p입니다. CSV 지표를 바꾸거나 경제적 인과를 확정하지 않습니다.

18개 자동 검증은 전체 904개 이벤트의 계보 값·기업·기간·공시·PIT·CFS/OFS, 실제 스키마, 합산 불일치 표시를 포함합니다. 브라우저 검증 결과는 `lineage-ui-validation.json`에 별도로 기록합니다. 3분 이해도는 실제 사용자를 대상으로 별도 평가해야 합니다.


## 데이터 수집·처리 과정 및 공통 보고서 패널

독립 메뉴에 전체 흐름, 데이터 출처, 보고서/재무제표, CSV 구조, 컬럼 상세, 분기변환/TTM, 공시 날짜/PIT, 품질/오류, 실제 원문 탐색의 9개 화면을 추가했습니다. React Flow 12.12.0·React 19.3.1을 로컬 번들로 사용하며 외부 CDN을 호출하지 않습니다. 축소로 가독성이 떨어지는 모바일에서는 확대·이동 및 단계 바로 선택을 제공합니다. 전체 출처 패널은 기업 분석·수식 계보·CSV·분기 비교·원문 목록에서 공유합니다.

추가 지정 폴더 `OpenDART_TTM_팀원전달_최종본-20261021T062432Z-1-001`의 주요 6개 CSV는 활성 최종본과 바이트 단위로 동일함을 확인했습니다. 활성 데이터는 그대로 유지했습니다. `derived/source_reports.json`은 기존 접수번호를 키로 보고기간·공식 접수일·공개시각 NULL·검증 상태만 보강합니다. 기존 다대다 fact_id/접수번호 목록은 단일 보고서로 축약하지 않습니다.

`audit_20261021`의 공식 CORPCODE 원문 해시·20개 코드, 공식 공시목록·476개 보고서, 원문 경로·SHA-256을 연결합니다. 원문 경로는 서버 내부에서만 사용하고 절대경로를 응답하지 않습니다. 최종 패키지의 XML 51개와 별개로 기존 독립 감사 자료가 지정한 476개 원문을 읽기 전용으로 참조합니다. 이 경로가 다른 컴퓨터에 없으면 해당 사본은 ‘원천자료 없음’으로 처리하며 공식 DART 링크를 제공합니다.

- 보고서 날짜는 원문의 COVER `PERIODFROM/PERIODTO` 태그를 사용합니다. 449건은 태그 날짜를 확보했고 파생 분석용 XML 27건은 기간 태그가 없어 NULL입니다. 파일명·회계연도만으로 날짜를 만들지 않습니다.
- 476건의 원본 `rcept_dt`는 14자리 형식 오류가 있으나 공식 목록의 8자리 접수일과 저장 공개 날짜는 대조됩니다. 원본을 수정하지 않고 공식 접수일을 따로 제공합니다.
- 공개시각·정정 공개시각은 전부 NULL입니다. 날짜 수준 대조·익거래일 적용·거래 가능성 검증을 구분합니다. 정정본은 이용 가능일 전의 분석에 사용하지 않습니다.
- API 3분기 보고서 코드 `11014`와 XML 분기 양식 ACODE `11013`은 서로 다른 체계입니다. 저장된 XML 양식 필드와 실제 XML을 비교하며 두 체계의 차이를 오류로 오인하지 않습니다.
- 단일 원천 행의 BS/IS/CIS/CF는 지정 표 앞의 실제 재무제표 표제와 연결 범위가 확인될 때 보강합니다. API 계정 ID는 같은 기업·종목·접수번호·연도/분기·보고서 코드·CFS/OFS·제표·계정명·KRW 금액·당기/누적 열이 유일하게 대응할 때만 보강합니다. 비교기간·다중 ID·미일치는 NULL로 남깁니다.
- 독립 감사의 확인 오류 3건은 052270/OFS의 매출 TTM·PM·ATO·OpROA 영향입니다. 원본 값은 보존하되 계보와 차트 근거에서 경고합니다. 별도 검토용 격리본을 자동 적용하지 않습니다. CSV 산식 통과는 원문 금액·의미 전체의 검증 완료가 아닙니다.

추가 API는 `/api/files`, `/api/file-profile?file=<허용목록 ID>`, `/api/column?file=<ID>&column=<실제 컬럼>`, `/api/source-fact?fact_id=<ID>`, `/api/reports`, `/api/quarter-compare`, `/api/pipeline-quality`입니다. 파일 탐색은 서버 소유의 ID 목록만 허용합니다. 전수 행 수·컬럼·결측은 파일 전체 범위이며 예시는 선택 기업·재무제표·분석일로 제한한 최대 3행입니다. 모든 재무 예시가 해당 시점에 이용 가능해야 하며 미연결 컬럼은 자동 공시 연결을 하지 않습니다.

`python dashboard/build_provenance.py`로 별도 메타데이터·매핑 결과를 생성합니다. 원본 CSV 7개의 SHA-256은 작업 전후 일치합니다. 브라우저 검증은 `pipeline-ui-validation.json`·`lineage-ui-validation.json`, 자동 18개 테스트는 `validation.json`에 기록합니다. 실제 사용자 이해도 평가와 외부 배포 권한 검토는 별도 과제입니다.
